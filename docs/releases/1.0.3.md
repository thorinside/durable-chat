# durable-chat 1.0.3

Patch release containing the reviewed pagination and reset-recovery fixes from
[PR #11](https://github.com/thorinside/durable-chat/pull/11), on top of 1.0.2.

## Complete job response pages

- Durable job receipts retain the entire final text response instead of a
  6,000-character tail. Completion notices contain page 1, not an
  800-character summary. Main's `task` tool supports `action: "result"`;
  terminal `show` also returns status and page 1. Job lists remain compact.
- Pages target **~5,000 estimated tokens**, using UTF-8 bytes / 4 (rounded up),
  not a tokenizer or a true token upper bound. A page has at most 20,000
  content bytes and 1,400 newlines; the line budget can produce smaller pages.
  Whitespace, code, long lines and Unicode text are preserved without splitting
  surrogate pairs.
- Follow each exact `nextCall`, including its `revision`, until
  `remainingPages` is zero before judging the full response. Pages after 1
  require that revision; invalid pages and changed revisions return errors.
  Boundaries and revisions are stable across restarts for the same response.
  Live jobs reject result paging: settled-page retrieval is not status polling.
- In codemode print one page's `display` per script, with the default 10,000
  output-token budget (at least 6,000). Batching displays or reducing that
  budget can still truncate output. For exact reassembly concatenate structured
  `text` fields in page order, not display wrappers. Metadata includes page
  counts, remaining bytes/estimated tokens, UTF-16 offsets and the next call.

## Immutable answers and reset recovery

Settled answers are read from the original immutable child-conversation entry,
not only the active context or Main's entry scope. Reset/compaction therefore
does not turn an available settled answer into an empty result. Valid empty and
whitespace-only responses remain valid; a missing, wrong-conversation or
non-assistant entry is not proof of an empty answer.

Pre-pagination jobs recover complete text from their original `answerEntry`
when available. If that entry is unavailable and the stored answer is a known
truncated legacy tail or is not known to be complete (including unproven empty
legacy text), retrieval reports the limitation rather than claiming completeness.
No lost source text is recreated.

## Scope and compatibility

Paging retrieves final response text, not thinking, images or the full transcript.
A handoff's stored response is its summary; failed/aborted receipts expose their
recorded reason when no answer exists. CLI/TUI transcript and detail previews
remain separate inspection surfaces, not paging sources.

Node.js 22.19.0 or newer is required. Both `dchat` and `durable-chat` aliases
remain available. Dependencies, provider/authentication behavior, MCP behavior
and Main-only image attachments are unchanged. The closed, unmerged
authentication PR #1 is excluded. This release does not change source wrappers
or global installations.
