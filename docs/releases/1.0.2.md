## Transcript copying

- Local interactive macOS copying uses the native clipboard writer with `pbcopy`
  fallback, including local tmux. Selection clears only after a successful local
  write. SSH never writes the remote Mac's clipboard; OSC 52 delivery remains
  unconfirmed and depends on terminal permissions and tmux passthrough. Apple
  Terminal does not support OSC 52.
- Selection excludes display gutters, padding, code fences and enclosing code
  rails while preserving selected code indentation, blank lines and literal rail
  characters. Soft-wrapped fragments of the same code line are rejoined; real
  code newlines remain.
- This is not byte-exact source export: toolkit tab/indentation normalization,
  lost right-edge wrap spaces and extremely narrow nested blocks still limit
  reconstruction. Only selected visible rows are copied; prose retains rendered
  row boundaries. `y` outside the composer still copies the full underlying
  answer, including Markdown. See [copy limitations](../transcript-copy.md).

## Dashboard and job input

- Ctrl-X or `/context [on|off|toggle]` saves context-pane visibility in the active
  config. Enabled panes appear only when there is room (at least 140 terminal
  columns and 80 transcript columns); resizing does not change the saved choice.
  The focused footer lists primary actions and a route to full help.
- Job IDs reserve seven numeric cells so longer IDs remain readable.
- Enter (or `s`) in the jobs pane pins the highlighted job and immediately focuses
  the composer, preserving the draft and attachments without sending them.
- Plain Enter to a running job defaults to steering at the next supported
  boundary, not interruption of an in-flight model request or tool. Admission is
  not a delivery/completion guarantee; refused sends preserve the draft. Main
  and completed-job conversations continue to default to follow-up.
- Command-Shift-Enter queues one follow-up behind the current run without changing
  the next Enter's behavior. This requires Command/Super plus Shift in CSI-u/Kitty
  input; terminal/macOS bindings may intercept it. Legacy input and xterm
  modifyOtherKeys cannot distinguish the required Super modifier. Use
  `/send <id> <message>` when unavailable; `/steer <id> <message>` explicitly
  requests steering. No terminal settings are changed. Alt-S no longer toggles
  input mode; Option-S remains text. Shift-Enter remains newline, with Ctrl-J or
  Alt-Enter as fallbacks.

## Compatibility

Node.js 22.19.0 or newer is required. Both `dchat` and `durable-chat` aliases remain
available. Dependencies, Main-only image attachments and MCP authentication
behavior are unchanged. The closed, unmerged authentication PR #1 is excluded.
